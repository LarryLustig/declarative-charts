Label Positioning

Control where labels appear on chart elements using label-position and offset attributes. Settings cascade from chart to element.

Position Attributes

Attribute Type Description
label-position string Where to place the label (values depend on element type)
label-offset-x number Horizontal adjustment in viewBox units (positive = right)
label-offset-y number Vertical adjustment in viewBox units (positive = down)
label-offset-r number Radial adjustment (positive = away from reference point)

Bar Charts

Bar labels support 6 positions. "Top" means away from zero, "bottom" means toward zero.

PositionDescription
outsideOutside bar, away from zero (default)
inside-topInside bar, near value end
inside-centerInside bar, centered
inside-bottomInside bar, near zero line
outside-topAlias for outside
outside-bottomOutside bar, toward zero line

Crowded Labels

This library positions by data, so labels will collide. Two mechanisms, at two levels: label-collision on the chart handles the numbers drawn on the data, and label-rotate on <dc-axis> handles the names on the category axis.

Colliding Values (default)

<dc-chart width="500" height="350">
  <dc-line label="Plan">...</dc-line>
  <dc-line label="Actual">...</dc-line>
</dc-chart>

Every Label, Overlaps and All

<dc-chart width="500" height="350"
          label-collision="show">
  <!-- same two lines -->
</dc-chart>

Two parts to the default, in order, because the first loses no information. Clamping shifts a label sideways to keep it inside the plot — the first and last points of a line sit on the plot edges, so their centred labels otherwise hang over the axis gutter and land on the tick labels there. Then hiding drops what still overlaps, in document order. label-collision="clamp" does the first without the second, for when every number matters more than the overlap does.

Defaulting to hiding rather than showing is a judgement about which failure is worse. Two numbers printed on top of each other are unreadable and unmarked: the reader cannot tell there were two. A missing label at least leaves the shape it belonged to visible and correctly placed.

Tilting Category Labels

The category axis has more names than it has room. label-interval hides labels to make room; label-rotate keeps them. A tilted label needs roughly height / sin(angle) of horizontal space instead of its full width, so 45 degrees fits about three times as many.

Upright: Automatic Interval

<dc-chart width="500" height="400">
  <dc-bar value="20" label="North East Region"></dc-bar>
  <!-- seven more long names -->
</dc-chart>

Tilted: All Eight Fit

<dc-chart width="500" height="400">
  <dc-axis position="bottom" label-rotate="45"></dc-axis>
  <!-- same eight bars -->
</dc-chart>

The automatic interval knows about the tilt, so rotating stops labels being skipped rather than merely tilting the survivors. Padding grows to fit: both the depth below the axis and the sideways reach of the first label, which otherwise hangs off the edge of the chart.

Rotation applies to the category axis of a vertical chart. A horizontal chart puts its category labels in the left gutter, where they already run along the reading direction. Group labels stay upright and drop below the tilted tier — tilting both tiers makes an unreadable thicket.
