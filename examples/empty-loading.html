Empty & Loading States

What a chart shows when it has no data yet, or none to show at all

Empty Charts

A chart with no data elements draws a placeholder instead of the plot. The axes, grid and legend are dropped with it — they all describe data, so drawing them around nothing is noise. The title is kept, because it still says what the chart is about.

Default Message

<dc-chart width="500" height="350">
  <dc-title>Sales by Region</dc-title>
</dc-chart>
Sales by Region

Custom Message with <dc-empty>

<dc-chart width="500" height="350">
  <dc-title>Sales by Region</dc-title>
  <dc-empty>No sales recorded this quarter</dc-empty>
</dc-chart>
Sales by Region No sales recorded this quarter

Styling the Message

<dc-empty> renders as SVG text, so it takes fill and a unitless font-size in viewBox units — the same conventions as <dc-title>. Keeping the wording in markup also means your page's own translation applies to it.

Colour and Size

<dc-chart width="500" height="350">
  <dc-empty fill="#dc2626" font-size="22">Connection lost</dc-empty>
</dc-chart>
Connection lost

Themed with a CSS Variable

<dc-chart width="500" height="350" style="--dc-empty-color: #2563eb">
  <dc-empty>Nothing to report</dc-empty>
</dc-chart>
Nothing to report

All Elements Hidden

A chart whose data elements are all hidden is empty for a different reason, and says so. This is the state a filter UI produces when the filter matches nothing — distinguishing it from "no data was supplied" is the difference between a bug report and a shrug.

Every Bar Hidden

<dc-chart width="500" height="350">
  <dc-title>Filtered Results</dc-title>
  <dc-empty>No results match your filter</dc-empty>
  <dc-bar value="30" label="Q1" hidden></dc-bar>
  <dc-bar value="45" label="Q2" hidden></dc-bar>
</dc-chart>
Filtered Results No results match your filter

Unhiding Restores the Chart

<!-- Remove the hidden attribute and the
     chart re-renders on its own -->
<dc-bar value="30" label="Q1"></dc-bar>
Filtered Results No results match your filter

Loading State

Add loading while data is on its way. The chart shows a skeleton rather than an empty plot, so the space does not jump when the data arrives. The skeleton uses a fixed shape, not a random one — a placeholder that reshuffles every frame is a distraction.

Loading Skeleton

<dc-chart width="500" height="350" loading>
  <dc-title>Revenue</dc-title>
</dc-chart>
Revenue

Loading, Then Loaded

<dc-chart id="load-demo" width="500" height="350" loading>
  <dc-title>Revenue</dc-title>
  <dc-bar value="120" label="Jan"></dc-bar>
  <dc-bar value="150" label="Feb"></dc-bar>
  <dc-bar value="135" label="Mar"></dc-bar>
  <dc-bar value="180" label="Apr"></dc-bar>
</dc-chart>

<script>
  // when the data arrives:
  chart.removeAttribute('loading');
</script>
Revenue

When JavaScript Does Not Run

The states above are drawn by the library. This one is what happens when the library never arrives: <dc-chart> is a custom element, so with scripting off it is an unknown tag with no text of its own and the page shows nothing at all. The fallback has to come from your markup.

The simplest version is <noscript>, which costs nothing and never flashes, because the browser resolves it at parse time. It only covers scripting being disabled, though — not a bundle that was requested and blocked, 404'd, or rejected by CSP. To cover those, put the fallback inside the chart and hide it once the element upgrades:

dc-chart:not(:defined) { display: block; }      /* reserve space, avoid a jump */
dc-chart:defined .dc-fallback { display: none; }

:defined matches only once the library has registered the tag, so the table shows whenever it did not arrive and disappears the moment it did. The rule is required rather than decorative: the chart renders a catch-all <slot>, so a <table> left inside it is projected and painted below the chart forever. The trade against <noscript> is one paint of the table before the swap.

Fallback Inside the Chart

<dc-chart width="500" height="350">
  <table class="dc-fallback">
    <caption>Sales by quarter</caption>
    <tr><th>Q1</th><td>95</td></tr>
    <tr><th>Q2</th><td>80</td></tr>
    <tr><th>Q3</th><td>120</td></tr>
    <tr><th>Q4</th><td>105</td></tr>
  </table>

  <dc-bar value="95" label="Q1"></dc-bar>
  <dc-bar value="80" label="Q2"></dc-bar>
  <dc-bar value="120" label="Q3"></dc-bar>
  <dc-bar value="105" label="Q4"></dc-bar>
</dc-chart>

Keep the fallback to plain HTML. A chart reads its data from its direct children, so a dc-* element buried in the fallback is not drawn, does not reach the legend, and cannot move an axis — but writing one there still says something you do not mean. The values in the table are yours and unformatted — value-format applies to the chart, not to your markup — and they are stated twice, so emit both from the same template loop if you can.

Why This Matters

An empty chart is the state a data-driven page spends most of its early life in, and the easiest one to get wrong. Three things the library does deliberately:

  • The plot is replaced, not merely blank. Axes and a legend around no data look like a rendering failure rather than an answer.
  • The chart is not focusable while empty. tabindex drops to -1, so keyboard users are not sent into a chart with nothing to navigate.
  • The reason is logged. DC001 for no data, DC002 for everything hidden — so "why is this blank" is answerable from the console. The examples above set console-log="none" only to keep this page quiet.
