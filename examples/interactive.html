Interactive Examples

Popups, links, and charts that update themselves

Pop-Ups

A <dc-popup> inside a data element turns that element into its own trigger. trigger="hover" opens on pointer, trigger="click" on click — and because the popup body is markup you wrote, it can hold anything, including a link.

Dynamic Updates

Charts re-render when you change their markup, so the update is the DOM operation. Adding or removing an element changes the chart's structure; setting an attribute changes what an existing element says.

Adding and Removing Bars

<dc-chart id="dynamic-structure" width="500" height="350">
  <dc-title>Structure</dc-title>
  <dc-bar value="25" fill="#FF5722" label="A"></dc-bar>
  <dc-bar value="35" fill="#FFC107" label="B"></dc-bar>
  <dc-bar value="45" fill="#4CAF50" label="C"></dc-bar>
</dc-chart>

<script>
  function addBar() {
    const bar = document.createElement('dc-bar');
    bar.setAttribute('value', Math.floor(Math.random() * 50) + 20);
    bar.setAttribute('fill', colors[Math.floor(Math.random() * colors.length)]);
    bar.setAttribute('label', labels[labelIndex++ % labels.length]);
    document.getElementById('dynamic-structure').appendChild(bar);
  }

  function removeBar() {
    const bars = document.querySelectorAll('#dynamic-structure dc-bar');
    if (bars.length) bars[bars.length - 1].remove();
  }
</script>

Changing Values and Colours

<dc-chart id="dynamic-values" width="500" height="350">
  <dc-title>Values</dc-title>
  <dc-bar value="25" fill="#FF5722" label="A"></dc-bar>
  <dc-bar value="35" fill="#FFC107" label="B"></dc-bar>
  <dc-bar value="45" fill="#4CAF50" label="C"></dc-bar>
</dc-chart>

<script>
  function updateBar() {
    document.querySelector('#dynamic-values dc-bar')
      .setAttribute('value', Math.floor(Math.random() * 60) + 10);
  }

  // `fill`, not `color`. The `color` spelling was removed in 0.3.0, and
  // setting it now does nothing at all - silently.
  function changeColors() {
    document.querySelectorAll('#dynamic-values dc-bar').forEach(bar =>
      bar.setAttribute('fill', colors[Math.floor(Math.random() * colors.length)]));
  }
</script>

Live Data

Neither chart below is redrawn by hand. One appends a <dc-point> every five seconds, the other re-sets the value attribute on bars that are already there — and because a chart observes its own children, both re-render on their own. There is no redraw(), no setData() and no requestUpdate() in either script.

Streaming Line Chart

<dc-chart id="live-line" width="500" height="350" show-value="false">
  <dc-title>Requests per second</dc-title>
  <dc-line stroke="#2196F3" label="web-01">
    <dc-point value="46" label="1"></dc-point>
    <!-- five more seed points, then the script appends -->
  </dc-line>
</dc-chart>

<script>
  const line = document.querySelector('#live-line dc-line');
  let sample = 6;

  setInterval(() => {
    const point = document.createElement('dc-point');
    point.setAttribute('value', String(30 + Math.round(Math.random() * 50)));
    point.setAttribute('label', String(++sample));
    line.appendChild(point);
  }, 5000);
</script>
Requests per second

The series only grows, so the points pack tighter as it runs. The axis thins its own labels once they start to collide, and show-value="false" keeps a number off every point — at this density they are unreadable anyway.

Live Bar Chart

<dc-chart id="live-bars" width="500" height="350" show-value="false">
  <dc-title>Requests by region</dc-title>
  <dc-bar value="48" label="North"></dc-bar>
  <dc-bar value="35" label="South"></dc-bar>
  <dc-bar value="62" label="East"></dc-bar>
  <dc-bar value="41" label="West"></dc-bar>
</dc-chart>

<style>
  /* `part="bar"` is a public contract, and the same <rect> survives a
     re-render, so an ordinary CSS transition smooths the change. */
  #live-bars::part(bar) {
    transition: y 900ms cubic-bezier(0.4, 0, 0.2, 1),
                height 900ms cubic-bezier(0.4, 0, 0.2, 1);
  }
</style>

<script>
  const bars = document.querySelectorAll('#live-bars dc-bar');

  setInterval(() => {
    bars.forEach(bar =>
      bar.setAttribute('value', String(20 + Math.round(Math.random() * 60))));
  }, 5000);
</script>
Requests by region

The bars glide because the library reuses the same <rect> elements and exposes them as part="bar". Value labels are off here for a reason: <text> has no CSS y, so a number would snap to its new position while the bar beneath it was still moving.

The same two moves cover most live-data cases. Appending is for a series that grows; re-setting value is for a fixed set of things whose numbers change, and it is the cheaper of the two — no element is created or destroyed, so nothing but the geometry moves. Only the second can be smoothed this way, for exactly that reason: a transition needs an element that persists across the update.

Interaction Events

Charts emit dc-click, dc-mouseenter, dc-mouseleave and dc-render. Events are dispatched from the element in your markup — the <dc-bar> — and bubble, so you can listen on the element, the chart, or the document. Click and hover the bars.

Listening for Events

<dc-chart id="events-demo" width="500" height="350">
  <dc-title>Monthly Sales</dc-title>
  <dc-bar value="120" fill="#4CAF50" label="Jan"></dc-bar>
  <!-- three more months -->
</dc-chart>

<script>
  document.querySelector('#events-demo')
    .addEventListener('dc-click', (event) => {
      const { label, value, percent } = event.detail;
      // percent is a decimal: 0.25 means 25%
      showDetail(label, value, percent);
    });
</script>
